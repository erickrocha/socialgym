SocialGym on Kubernetes

The infra/helm/socialgym chart runs the whole backend — gateway, Postgres, Mongo, workout, integration, timeline — on a local minikube cluster in the socialgym-dev namespace. It is the Kubernetes counterpart to the infra/dev and infra/prod Docker Compose stacks. Every component is a single-replica Deployment fronted by a Service. 

# from the repo root
cd infra/helm/socialgym
./scripts/up.sh                                  # start minikube, build images, helm upgrade --install
minikube service gateway -n socialgym-dev --url  # reachable gateway URL

Config & secrets

cm gateway
nginx.conf — the route map above.
cm workout
HOST/PORT, password & login-lockout policy, non-secret AWS settings (region, bucket, SQS URL, CloudFront domain).
cm timeline
HOST/PORT, Mongo DB name, and the gRPC client config that points at integration over TLS.
cm mongo-init
init-app-user.sh — runs once on first boot to create the timeline app user.
secret socialgym-auth
ACCESS_TOKEN_SECRET / REFRESH_TOKEN_SECRET, auto-generated (64 chars), shared by workout, integration and timeline so JWTs verify across all three.
secret postgres
POSTGRES_PASSWORD, auto-generated. DATABASE_URL is assembled at container start so the Secret is the only copy.
secret mongo
root + app passwords, auto-generated.
secret workout / timeline
AWS access keys + CloudFront private key. Empty by default — image upload & signed URLs stay off until overridden.
secret socialgym-tls
kubernetes.io/tls. Created by kubectl, not templated by Helm; mounted by gateway, integration and timeline. SAN covers the integration Service name.

Related, and worth not confusing

  • workout/k8s/ is a separate Kustomize scaffold — Ingress, HPA, PodDisruptionBudget, NetworkPolicy, ResourceQuota — for workout-app alone, shaped for a cloud cluster. It is not part of this chart.
  • infra/dev/ (Compose, infra containers only; services run on the host) and infra/prod/ (Compose, everything containerized) are the non-Kubernetes ways to run the same stack.
  • Persistence: the postgres and mongo PVCs survive helm upgrade, but helm uninstall / ./scripts/down.sh deletes them — that wipes the data.
  • AWS: *.aws.* values are CHANGE_ME by default. AWS_SQS_QUEUE_URL must stay non-empty or workout's SQS consumer busy-loops and starves the HTTP server.
