# socialgym — local Kubernetes (minikube) chart

Helm chart that runs the whole SocialGym backend — nginx gateway,
PostgreSQL/PostGIS, MongoDB, `workout`, `integration` (gRPC), and
`timeline` — on a local [minikube](https://minikube.sigs.k8s.io/) cluster.
This is the Kubernetes-based counterpart to `infra/dev/` (plain Docker
Compose, infra-only) and `infra/prod/` (Docker Compose, fully
containerized) — pick whichever fits what you're testing.

It's a separate, self-contained chart, not related to `workout/k8s/`, which
is a cloud/production-shaped Kustomize scaffold for `workout-app` alone.

## Prerequisites

`docker`, `minikube`, `kubectl`, and `helm` on your `PATH`.

## Bring it up

```bash
./scripts/up.sh
```

This starts minikube if it isn't running, generates a fresh self-signed dev
TLS cert (gitignored, machine-local — see `scripts/gen-dev-certs.sh`),
builds `workout-app:local`, `integration-app:local`, and `timeline-app:local`
directly into minikube's Docker daemon (no registry needed), then
`helm upgrade --install`s the chart into the `socialgym-dev` namespace and
waits for every Deployment to become ready.

Reach the stack with:

```bash
minikube service gateway -n socialgym-dev --url
```

and hit the same routes documented for `infra/dev`'s gateway (`/login`,
`/signup`, `/auth/`, `/workout/api/`, `/timeline/api/`, `/grpc.*`).

## Tear it down

```bash
./scripts/down.sh                 # uninstalls the release, keeps minikube running
./scripts/down.sh --delete-cluster  # also stops minikube
```

Postgres/Mongo data lives in PVCs that survive a `helm upgrade` (the release
staying installed) but are deleted along with everything else by `helm
uninstall` - so `./scripts/down.sh` wipes your data too. If you want data to
survive between sessions, leave the release installed and just scale down,
or back up the PVCs yourself before tearing down.

## Secrets

Nothing here is ever committed with a real value:

- Postgres/Mongo passwords and the shared JWT `ACCESS_TOKEN_SECRET`/
  `REFRESH_TOKEN_SECRET` are auto-generated on first install (see the
  `secretValue` helper in `templates/_helpers.tpl`) and stay stable across
  `helm upgrade` by reading back the existing Secret. Override any of them
  via `--set` or `-f your-values.yaml` (gitignore that file) if you want
  reproducible values.
- TLS for the gateway/gRPC listener is generated by `scripts/gen-dev-certs.sh`
  into a gitignored `.dev-certs/` directory next to this chart, then loaded
  as the `socialgym-tls` Secret directly via `kubectl` (not templated by
  Helm, so it never touches a values file).

## Known limitation

`workout.aws.*` / `timeline.aws.*` values are empty by default. Avatar/cover
image upload and CloudFront-signed URLs won't work against real AWS unless
you override them with real credentials (`--set workout.aws.accessKeyId=...`
etc, or a values file). Core social-graph, auth, and workout/timeline
endpoints don't depend on AWS to come up.
